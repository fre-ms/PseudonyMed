# PseudonyMed – Manual

PseudonyMed redacts patient documents on your own computer before you hand them to a language model, and puts the clear data back afterwards. Nothing leaves the computer except the search in your own Nextcloud address book (PseudonyMed reads the Mac's Contacts app on the computer itself).

## Installation

**Packaged:** unpack the archive for your system (macOS: drag `PseudonyMed.app` to Applications; Windows and Linux: put the folder `PseudonyMed` anywhere). It contains the desktop interface `pseudonymed-gui` (macOS: the app) and the command line `pseudonymed`. The packages are not code-signed; macOS asks on first start (right-click, Open), Windows shows the SmartScreen notice.

**From source:** Python 3.12 or newer and [uv](https://docs.astral.sh/uv/), then

```sh
uv sync --extra gui
uv run pseudonymed gui --language en
```

Tesseract is used as a second OCR engine when it is installed (macOS: `brew install tesseract tesseract-lang`, Ubuntu: `apt install tesseract-ocr tesseract-ocr-deu`); it is found in the usual places even when the app is started from the Finder. It is not required, RapidOCR is included (it comes with docrepro, PseudonyMed's document layer, as do the clean-up, the binding of photos into a PDF and the barcode search). To prefer Tesseract, put `backend = "tesseract"` under `[ocr]` in the configuration file (`pseudonymed config` shows the path) or set `PSEUDONYMED_OCR=tesseract`.

**Language.** The interface follows the system language: German on a German system, English on any other; `--language en` or `--language de` on the command line, the menu *Language* in the window, or `PSEUDONYMED_LANGUAGE=en` choose it explicitly. The command line follows the same setting (`pseudonymed --language en <command>`, `PSEUDONYMED_LANGUAGE`, `[gui] language`, else `LANG`). In English every message, every help text, the control step and the reports (`.report.json`, the vocabulary file) are English; commands and options have a German and an English name, and both work in either language, so that scripts run anywhere (`pseudonymise` or `pseudonymisieren`, `database status` or `datenbank status`, `--target` or `--ziel`); the help lists the commands under the names of its language and shows each option's two names, its language's first. The words an option takes as its value come in German and in English too (`year` or `jahr`, `age` or `alter`, `off` or `aus`, `replace` or `ersetzen` …), and both work in either language; the help names those of its language. Pseudonyms such as `[geb. 1959]` or `[Ort …]` stay German in either language, because they are part of the German document.

**Files.** What PseudonyMed writes is English in either language: the keys of reports, working states, capsules and backups, the tables of the pseudonym database, the configuration `config.toml`, the file names (`<name>_pseudonym.report.json`, `<name>.working-state.json`, `pseudonyms.sqlite` …) and the values in them (`surname`, `birth_date`, `green` …); only the messages inside a report are in the language of the run. Where people write by hand, the German names are understood as well: a patient file may say `nachname`, `vorname`, `angehoerige` … instead of `surname`, `first_name`, `relatives` (`pseudonymed template` writes it in the language of the command line), the configuration `[speicher] datenbank` instead of `[store] database`, the environment `PSEUDONYMED_DATENORDNER` instead of `PSEUDONYMED_DATA_FOLDER`. The classes of identifiers and the categories of the vocabulary are stored in English as well (`hospital`, `occupation`, `body parts` …) and shown in the language of the interface; an imported list or the command line may name them in German (`Klinik`, `Körperteile`). The bundled lists in `pseudonymed/data/` have English names and columns; their terms are the German words of the documents, and so are the words in pseudonyms (`[Klinik …]`).

## First start

PseudonyMed creates the pseudonym database (`pseudonyms.sqlite`) and the secret key next to it (`pseudonym-key.txt`) in the user data folder; `pseudonymed config` shows the paths. **Back up the key.** With the same key every computer produces the same pseudonyms; without it old identifiers cannot be reproduced. The database holds the mapping pseudonym → clear data for re-identification; it is patient data and stays on the computer. `PSEUDONYMED_DATA_FOLDER` puts database, key and configuration into one folder, for a portable installation on an encrypted stick.

Set up the address book once (command line):

```sh
pseudonymed contacts setup --url https://your-nextcloud.example --user yourname --address-book patients
```

The app password (Nextcloud → Settings → Security) goes into the operating system's keyring.

On a Mac it also works without Nextcloud and without an export: `pseudonymed contacts mac --on` searches the Contacts app (every address book there; `--address-book iCloud` picks one, and may be repeated). The first time, macOS asks whether PseudonyMed may read the contacts; the answer can be changed under System Settings → Privacy & Security → Contacts. What is read: name, salutation and title (the *prefix* field), maiden name, date of birth, address, phone, e-mail and job title. macOS hands out notes only to programs holding a separate permission from Apple, and the Contacts app does not pass on a vCard's own fields (such as the Doctolib patient ID): if you need those, search through Nextcloud. A patient found in several address books is listed once.

## The fourteen steps

1. **Patient data.** Search the address book (name, year of birth), load a patient file or a vCard. Address books are set up under *Set up address books …*: a local vCard file or a folder of vCard files (exported from Thunderbird, Outlook or Nextcloud; stays on the machine), on a Mac the address books of the Contacts app (tick which; macOS asks for permission when they are first loaded) and/or Nextcloud over CardDAV (address, user, app password from Nextcloud → Security; the password goes into the keyring, or into the configuration file where there is no keyring). Hits appear in a list that shows only when there are hits; a click fills the fields. *Patient file …* loads a JSON or TOML file with the identifiers as `pseudonymed contacts export` writes them; *Save template …* gives an empty one to fill in. Check the fields: everything listed there will be redacted. Add relatives, referrers and further terms (one per line) or drop a text file with one entry per line onto the field; they are not taken from a contact's notes automatically. *Use this patient*.
2. **Identifiers.** What leads to a person besides the patient data without being medical: hospitals (hospital directories of Germany and Switzerland, Austria on request in *14 Database*), occupations (German classification of occupations 2010), study acronyms (ClinicalTrials.gov, DRKS), titles and your own entries (employers, clubs, institutions; class *Other*). The table works like the medical vocabulary: search, filter by class, edit cells, add, delete, export and import CSV. Like the patient data, identifiers are redacted by default (placeholders such as `[Klinik 7HQ2NB]`, `[Beruf …]`, dashed in the visual review and discardable), but only in context: hospital names wherever they stand (the official name, its main part, or *Klinikum, Krankenhaus … + town* for towns with a hospital), occupations only next to cues such as *arbeitet als*, *gelernter*, *ist*, *von Beruf* or in the social history, study acronyms only in the registered spelling next to *Studie* (registry numbers such as NCT or DRKS always), titles only directly before or after a name that was found, your own entries everywhere. Every listed spelling of an entry is looked for. Where a place fits more than one class (an acronym of a study that is also an occupation, say), it is redacted once and named after the first of hospital, occupation, study, a class of your own, *Other*. Employment status (retired, unemployed) stays, following the GeMTeX guideline. Deleted bundled entries stay deleted across updates until you restore them; changed ones become your own. The entries are not in the pseudonym database: they live in `lexident.sqlite`, the store of lexident, the library that recognises such identifiers, beside the store of the vocabulary (`pseudonymed identifiers status` shows the path). Every list is a package there, your own entries are lists called *Nutzer: class*, and what you deleted is hidden, not removed. As with the vocabulary, only the store's own lists are PseudonyMed's: a directory another program keeps there under an address of its own is never changed, and it is looked for while it is ticked in *Lists and terminologies* above the table (see below). A database that still holds the identifiers of an earlier version hands them over on first start, checked entry by entry before its tables go. The box in *9 Analysis* switches the redaction off.
3. **Medical vocabulary.** Every term NER and the fuzzy search must never redact, as a sortable table (term, category) over the store of lexterm, the library that keeps medical terms: the bundled lists (medicine from Wikidata, body parts, findings terms, eponyms) are installed there on first start, each category as a package of its own. Search, sort by column (header), change cells by double click, add and delete terms (bundled ones too, "Wolf" say), export CSV and import CSV or lists (one term per line, for instance the `.vocabulary.txt` written on export). A deleted term is hidden in the store rather than taken out of its list, so it stays away when the list is installed again; *Load the bundled lists again* brings deleted base terms back. Above the table, *Lists and terminologies* shows the lists of the store with a box to tick (see below). Command line: `pseudonymed medical-terms status|add|remove|export|import|merge`.
4. **Documents.** Drop PDFs, photos or text files (`.txt`, `.md`, `.srt`, `.vtt`, Whisper `.json`, `.eml`, for instance the transcript of a recorded consultation or a patient's e-mail); they are opened at once, every PDF and image in docrepro's chain: a photo or an image is bound into a PDF by typdoc as the records standard medRDS says (the picture byte for byte in it, a page with the long side of A4, upright as its EXIF orientation says), because PseudonyMed redacts PDFs. A working state saved in the review (`name.working-state.json`, or the original `name.working-state.<ending>` beside it) fills everything in again up to and including *10 Visual review*: patient data, preparation, text recognition with its corrections, hits, discarded hits, boxes, masks and take-ups; the window goes straight to the review. Text files need neither preparation nor text recognition. *Next: prepare*.
5. **Prepare.** Steps 5 to 8 are docrepro's own panels: on the left the documents and their pages, on the right the panel on the page chosen. Here optdoc's: the page before and after. Every page without a text layer of its own (scans, photos) comes with optdoc's suggestion: turned upright, a photographed sheet found and unwarped in its true proportions (drag the blue corners in *Before* onto the sheet's corners), the tilt straightened (angle adjustable), the background evened out in every colour channel (the paper becomes white, ink keeps its colour), stored in grey where the page has no colour; under *Further steps* clean dark borders, denoise, raise the contrast, sharpen, each with a strength from 1 to 5; *Detect the orientation* (portrait or landscape from the lines, upside down by a short OCR comparison, at once with the orientation model where it lies in the models folder) and *Rotate*. Dragging on *After* erases the area white (Cmd/Ctrl+Z takes it back, *Take back all*). *Restore the suggestion*, *Do not clean up this page*, *Copy the steps to every page*. The page keeps its colours (stamps and blue signatures stay on it); a page with a text layer of its own stays as it is. Upscaling, the letter mode and taking coloured ink or lines away are no longer done to the page: they are filters of the text recognition (step 6). *Next: filters for OCR*.
6. **Filters for OCR.** Above, the settings of the text recognition: the OCR engine (RapidOCR with bundled models, Tesseract, off) and its language packs (Tesseract: `deu+eng`, the installed languages are listed; RapidOCR: language type `de`, `en`, `latin`). Tesseract takes a bordered table for graphics and skips the cells (a medication table came back as a single word); its second pass therefore looks for grids on every page, cuts them out, removes the rules and reads the crop as one block; the better reading wins (measured on synthetic tables with thick borders: 0 of 45 cell words without, 42 with the second pass). The *Tables* checkbox switches it off; RapidOCR does not have the problem. With *Structure the recognised text* (on by default) the recognised text goes out as Markdown: lines that run to the right margin are joined into paragraphs (hyphenation undone), a taller gap ends the paragraph, lines in a larger face become headings, short bold lines on their own small headings, bullets list items, words far apart table cells (several such lines a Markdown table); italics are not recognised, the engines report no slant. *Start text recognition* reads every document: ocrdoc reads each page it has not read yet; with another engine or other language packs the pages are read again, and what was decided in steps 6 to 8 goes. Below, ocrdoc's filters of the page chosen, which change only the copy the OCR reads, never the document: upscale 2×, 3× or 4× (the OCR reads the page at that multiple of the resolution, at most 9000 pixels), letter mode (grey, strokes sharpened, best with upscaling; a hard black-and-white threshold lowered the recognition markedly in measurements), take coloured ink away (stamps, highlighter, blue signatures; they are found as areas), take ruled lines away (forms, tables), black and white. ocrdoc suggests upscaling below 150 dpi and taking coloured ink away where more than 0.3 % of the page is coloured. What a filter takes away the text recognition does not see, and what it does not see PseudonyMed can neither search nor redact: such a page therefore goes out as it was read, without the coloured ink, the lines or the shades of grey its filters took away (the visual review shows it so already, the report names the pages). docrepro itself keeps the colours. For a stamp to be searched and to stay, take the filter back on that page; then the text recognition reads it as well. *Restore the suggestion*, *No filter on this page*, *Copy the filters to every page*. *Next: areas*.
7. **Areas.** ocrdoc's areas of the page: text, tables with their grid of rows and columns, pictures, barcodes (with their content), handwriting, stamps, and areas not to be read; found by ocrdoc and set by hand (draw an area of a kind, move it, change its kind, add or remove a table's lines, merge cells). What lies in no area is read as text; the numbers are the order of reading. Pictures, barcodes and areas not to be read stay out of ocrdoc's text, but PseudonyMed searches every word OCR read on the page all the same, whatever area it lies in, so that nothing printed escapes the search; barcodes and QR codes are blanked by PseudonyMed's own code search. *Next: check the text*.
8. **Check the text.** The page as the OCR read it (yellow: words read with little confidence; a click on a word selects it in the text) next to the recognised text, which you correct by hand on OCR pages; a gap between table cells is a tab. Text from a text layer cannot be changed; *Back to the OCR text* takes a correction back. The correction feeds the text file, the Markdown and the invisible text layer, and the analysis searches it as well; what the OCR misread in the image you redact later with a box or a mask. The invisible text layer of the PDF sits word by word on the image words: for corrected or structured text every word is aligned to the OCR word it came from (a corrected word takes the box of the one it replaces, inserted words sit between their neighbours, Markdown characters get no box), so that text can be selected in a PDF reader exactly where it is printed. What a person did in steps 5 to 8 is kept by docrepro's own rule: a later step keeps what was decided on a page as long as the steps before leave the page where it lay (more contrast in step 5 keeps filters, areas and corrections; a rotation or another unwarping drops them, and the status line says so). If that happens after a document was analysed, the list in *4 Documents* says *changed: please analyse again*. *Next: analyse*.
9. **Analysis.** *Analyse* searches new documents, *Analyse again* also those analysed already, with the current settings: the preparation, filters, areas and corrections of steps 5 to 8 count as they stand now, boxes, masks, take-ups and discarded hits are taken over (but not the boxes, masks and take-ups of a page that lies otherwise now, turned or unwarped anew in step 5: they would cover something else, and a warning names the page). That is how variants of the same document come about without starting over. The detection settings: form of the date of birth, barcodes, unreadable lines, medical terms, fuzzy search in text files (speech recognition misspells names the way OCR does), NER, and four options for the medical content, all off by default because medications and lab values belong to the content: *Medikamente: Substanz schwärzen* replaces the drug name from the lexicon by `[Medikament …]` (names that also denote a disease, such as *ASS*, stay); *Medikamente: Dosierung und Verordnungsschema schwärzen* replaces what stands next to a substance by `[Dosierung …]` (*500 mg 1-0-1*, *2 Tbl.*, *bei Bedarf*, *p. o.*), the substance stays unless chosen separately; *Laborwerte: Untersuchung schwärzen* replaces the name of the examination wherever it stands by `[Laborwert …]`; *Laborwerte: Messwert schwärzen* replaces the value after an examination by `[Messwert …]` (*2,3 mU/l*, *< 5 mg/l*). The four levels are independent: knowing the substance is one thing, knowing dose and schedule another; knowing what was examined is one thing, the value another. A term on both lists (*Kalium*) is a lab value when a measurement follows and a medication when a dose follows. Trade names the lexicon does not know (Marcumar, say) go into *3 Medical vocabulary* with the category *Medikament*, your own lab names with the category *Laborwert*. The re-identification puts everything back. Below it the statistics of the medical vocabulary (edited in *3 Medical vocabulary*) and *Recipient*: whoever pseudonymises for someone else (see key capsules) gives that person's public key here. Defaults: mark and protect medical terms, then NER (if the extra is installed). Below it the medical vocabulary with its sources and *Import vocabulary …*: a text file with one term per line, for instance the `.vocabulary.txt` written on export, is merged into your own vocabulary and protected from the next analysis on. *Analyse* searches all read documents with a progress bar; the review step opens afterwards.
10. **Visual review.** Redaction only now; the text is no longer edited here. Traffic-light colours: red will be redacted (dashed when NER or the fuzzy search merely suggest it), yellow was read with low confidence by the OCR (unreadable lines are blanked as a precaution), green stays: medical terms and discarded hits, which remain visible and can be restored with a click. The source of every hit is in the table. A false hit (a drug name that looks like a surname): click it, *Discard hit*. Dragging draws a box with the replacement text from the field next to the buttons; with *Draw mask* a black mask under which text and image disappear; Shift + drag pans the view, Ctrl/Cmd + wheel zooms. *Remember discarded hits for this patient* stores your decisions in the pseudonym store on export: in the next document of the same patient the same text under the same rule starts out green and can be restored. What the OCR misread in the image you redact with a box or a mask; the text itself is corrected in *8 Check the text*. Something missed, a handwritten name for instance: drag a box over it. Zoom with Ctrl/Cmd and the wheel or the buttons. Something the analysis did not find, or a medical term that stays green, gets into the list with a click on the word (blue) and *Take up selection*; Ctrl/Cmd + click extends the selection to the clicked word. With the default *[geschwärzt]* left in the replacement field, a word taken up gets a code of its own, `[Begriff …]`, which the re-identification puts back; otherwise the text entered. *Save working state …* writes the original as it came (`name.working-state.pdf`, `.jpg` …) and a configuration file (`name.working-state.json`) with docrepro's chain document and everything made so far; both contain clear data and are kept like the original. Dropped on *4 Documents* again, the review can be resumed or varied. A text file appears as text with coloured spans instead of a page image; click a span to select the hit, select text and press *Take up selection* to turn it into a manual hit. Orange spans are the fuzzy search's hits: suggestions worth a look.
11. **Control.** Two lights before the export. The first is the re-check: the complete finishing phase runs into a scratch folder and the result is searched for everything from *1 Patient data*; red means something was still found, so rework. The second is the residual risk: an estimate of how many people share what the text still says. It follows the k-map idea of disclosure-risk assessment (El Emam, EMA Policy 0070 with its threshold of 0.09, Rocher et al. 2019): sex (1 bit), year of birth or age (about 6.4 bits), the smallest named place by population (Destatis municipality directory) and the rarest named rare disease by Orphanet prevalence are converted into bits; about 26.3 bits single one person out of Germany. λ is the expected number of people sharing the details, κ the chance that a match is the right person. Green from λ = 11 (κ ≤ 0.09), yellow from 5, red below. Flags name what the model cannot weigh: ages from 90, year of birth and age next to exact dates, dated reportable events, occupation, family details, places under 20,000 inhabitants. All documents of the same patient are judged together, released ones included (only categories and weights are remembered, never clear text). Reference population (Germany or the catchment area of the consultation service) and own places (consultation service, clinic) are settings. The estimate is a synthesis of published parts, not a standard, and assumes independent attributes, which is optimistic for atypical combinations; it points the review to the detail with the largest contribution. Red does not block the export but requires an explicit confirmation. The computing is done by the library identicalc (model, weights, population and prevalence data); the report names its version.
12. **Export.** The lights of *11 Control* (re-check and residual risk) appear here again; whoever skipped that step gets the re-check on opening. The first light shows the outcome: green means nothing found any more, ready to export; yellow means released but with warnings you should read; red means data were still found, the export button stays off and a message names the leftovers, which you rework in the review step with a box or a mask. The export then copies the checked files. The report records what was searched again ("Erneut geprüft nach dem Prüfschritt: …") and which hits you kept on purpose; your deliberate decisions and general reminders (clean-up steps, OCR summary, the note that handwriting is not read, blanked unreadable lines, NER counts, fuzzy hits, remembered discards) are listed under *Hinweise*, only what needs attention under *Warnungen* (pages without OCR, NER requested but missing, an uncertain patient match, a failed re-check), and only those turn the light yellow; a passed scan is green. With *Vocabulary of the discarded guesses* (on by default) you also get `name_pseudonym.vocabulary.txt`: the NER and fuzzy hits you discarded in the review, one term per line, for the import in *3 Medical vocabulary*; discarded hits of the fixed rules are left out, their text being one of the patient's identifiers. Choose a target folder. Per document you get `name_pseudonym.pdf` (with a text layer: for scans and photos the OCR text minus the hits is embedded invisibly, also after *rasterise completely*), `name_pseudonym.txt` (the text in reading order, this is what you give the language model), optionally `name_pseudonym.md`, and `name_pseudonym.report.json`; a text file yields only `name_pseudonym.txt` (same extension as the input, subtitle timestamps preserved) and the report. The re-check reads the result again; if an identifier survives, nothing is released and the report says why. OCR pages get preview images: look at them before you pass a scan on.
13. **Re-identification.** Paste the language model's text, pick the person, *Re-identify*. If the text comes from someone else, open their key capsule (*Open capsule …*, see below); its mapping then replaces the local database.
14. **Database.** Where database and key file live (any folders, even apart; a change copies the current files there and renames the old ones), statistics of the pseudonym store (patients, mappings per category, remembered discards, size, integrity, key handle) and backup and restore of everything re-identification needs: database and key file, the identifiers, optionally configuration and vocabulary (vocabulary and identifiers are not in the database; the vocabulary travels in the archive as a CSV, the identifiers as a store that holds PseudonyMed's lists and nothing another program keeps beside them). The backup is a ZIP with checksums, encrypted with a passphrase (`.zip.gpg`, `gpg --decrypt` opens it too) or, if you insist, plain. Restoring replaces database and key (the current ones are set aside) or merges an archive made with the same key; two different keys cannot be mixed. The vocabulary follows: restoring makes it exactly what the archive holds, merging adds what is new, and without the box it stays as it is. So do the identifiers: restoring makes the lists exactly those of the archive (yours are copied aside first, like database and key), merging adds those of your own entries that are new. Nothing is imported while analysed documents are still waiting for export. Under *Additional data*, *Fetch from the ministry* loads the current list of Austrian hospitals straight from the ministry of health into the store of the identifiers on your computer (or *From file …* a workbook you downloaded yourself); PseudonyMed does not bundle it because the ministry permits reprinting only for non-commercial purposes. Command line: `pseudonymed database status|export|import|extra-data hospitals-at`. *Mr/Ms surname* inserts the salutation by grammatical case, *full name* the name. Mangled pseudonyms (wrong check character) are reported with a suggestion.

## Texts and transcripts

If you record consultations and transcribe them locally, the transcript is a text file: it runs through the same detection as a PDF, and the result is text again with pseudonyms and nothing else changed. Particulars: the fuzzy search finds the patient's name even when misspelt ("Flanz" for "Flantz") but requires a capital letter for names and places; at the start of a sentence it may suggest similar words ("Land" for Lang), which you discard in the review step. `--exact` switches it off. Numbers spoken as words are read as digits before matching: "am einundzwanzigsten Juli neunzehnhundertneunundfünfzig" is the date of birth, "Sieringgasse zweiundvierzig" the street, "acht zwei vier sechs zwei" the postcode; the whole phrase is then replaced.

**Whisper JSON** (openai-whisper, whisper.cpp, WhisperX) is rendered as one line per segment with timestamp and speaker and written as `.txt`; word timings and token ids are not carried over, because the token ids hold the clear text in another form. **E-mails** (`.eml`, dragged or exported from the mail program) become From, To, Cc, Date, Subject, the body (from HTML if need be) and a list of attachment names; routing headers such as Message-ID are left out and attachments are not included: pseudonymise an attached PDF or photo as a file of its own.

## What is redacted and what is not

Redacted: the name in all spellings, the date of birth in all formats, address, telephone, e-mail, insurance number, patient ID, file numbers, the relatives and referrers you entered, barcodes, and generically every insurance number, IBAN and e-mail address as well as values behind labels such as "Versicherten-Nr." or "Pat.-ID". With NER switched on, additionally people and places the model recognises.

Redacted by default but discardable in the visual review: identifiers from *2 Identifiers* (hospitals, occupations in context, studies, titles next to names).

Not redacted: diagnoses, medications and lab values (on request in four levels: substance, dose, examination, measurement; see *9 Analysis*), measurements, findings, appointment dates, employment status. Not recognised: unknown names when NER is off, and handwriting the OCR does not detect as text; the review step is there for that.

## NER

Named-entity recognition is a statistical model (spaCy, trained on German news) that tags person and place names in free text without a list. It catches the relative or colleague nobody entered, but it guesses: it may tag a drug or a department as a person, and it may miss a name. Therefore its hits are shown in their own colour in the review step, medical eponyms (Alzheimer, Parkinson, Babinski …) and everything the medical vocabulary marks are excluded, ordinary words that are only capitalised because they start a sentence ("Überwiesen hat Sie …") are dropped, and it never decides about the release. The graphical interface runs it by default once the extra is installed, after the vocabulary has marked the page; on the command line it stays opt-in (`--ner`). Install with

```sh
uv sync --extra ner
uv pip install https://github.com/explosion/spacy-models/releases/download/de_core_news_md-3.8.0/de_core_news_md-3.8.0-py3-none-any.whl
```

People it finds become `Person <code>`, places `[Ort <code>]`, with the same keyed hash as the patient's identifier, so the same name gets the same code and the re-identification knows it.

Context outweighs every list. A name right after a salutation, a title or a kinship word (*Dr. Becker*, *Frau Iris Nagel*, *Herrn Hoffmann*, *Ehefrau …*) is a person even where an eponym or a protected medical term is spelt the same (iris, nail, jaw: *Kiefer*); the name of a German municipality right after a preposition of place or a postcode (*in Essen*, *aus Pirna*) is a place. Without such context the lists decide, so *Kiefer: unauffällig* stays. The eponyms are only names that are rare among people; common surnames that also name a disease or sign (Becker, Weber, Hoffmann, Wilson, Turner and others, 33 in all, struck in November 2026) are no longer among them, and a store that still holds them in its list of eponyms hides them on the next start.

## Medical vocabulary: what guesswork must never touch

NER and the fuzzy OCR search run behind a guard: before they look at a page, every medical term on it is marked, and those spans are off limits to both. The deterministic rules for the patient's own identifiers are unaffected (a patient really called Herz is still redacted). The bundled base vocabulary (about 40 000 German terms) comes from Wikidata (CC0): German labels and synonyms of every item with an ICD-10 code, an ATC code, an INN or a MeSH descriptor in the medical MeSH trees (anatomy, organisms, diseases, drugs, techniques, psychiatry, phenomena); geography and occupations are excluded so that towns and surnames remain recognisable. Inflection, hyphenated compounds (*Parkinson-Syndrom*) and umlaut transliteration are recognised, multi-word terms as a whole.

A second bundled list (`body_parts_de.txt`, about 580 entries) covers body parts, organs, bones, muscles, vessels and nerves in everyday German plus side and position words (links, rechts, proximal …), because the Wikidata list lacks many colloquial forms (Kopf, Nacken, Oberbauch, Wade) and NER liked to take them for names. A third list (`findings_terms_de.txt`, about 370 entries) holds the terms of the clinical examination and the findings report as they head the lines of a status (Konzentration, Haltung, Gangbild, Strichgang, Nierenlager, Reflexe, Sensibilität, Procedere …), which are in neither MeSH nor the body-part list. On the order: the vocabulary marks the page first, then NER runs and skips every entity inside a marked span; NER also drops single words the tagger calls common nouns and unknown single words (compounds such as *Nierenlager*) without a salutation, title or preposition before them.

Your own vocabulary grows with every review: the export writes the discarded guesses to `name_pseudonym.vocabulary.txt`, and *Import CSV or list …* in *3 Medical vocabulary* or `pseudonymed medical-terms merge FILE` takes such a file into the vocabulary (category “User vocabulary”). The vocabulary shields terms from NER and the fuzzy search for every patient; for hits of the fixed rules there is the *Remember discarded hits for this patient* box in the review step.

Your own lists: `pseudonymed medical-terms import FILE --name CATEGORY` from MeSH XML (`--format mesh-xml`, the NLM file or a translation), from ICD-10-GM, Alpha-ID-SE or ATC tables (`--format csv --column N`) or from any plain list (one term per line); everything lands in lexterm's store, beside the bundled lists, and a backup takes it along. `pseudonymed medical-terms check WORD` tells whether a word is protected, `pseudonymed medical-terms status` lists the categories. SNOMED CT cannot be shipped (a BfArM licence is required); a locally licensed description file imports like any CSV.

Where the vocabulary lives: in `lexterm.sqlite`, the store of the library lexterm, in the data folder of the lex libraries (macOS `~/Library/Application Support/lexcor`, Windows `%APPDATA%\lexcor`, Linux `~/.local/share/lexcor`), where other programs that use lexterm find it; `pseudonymed medical-terms status` shows the path. When `PSEUDONYMED_DATA_FOLDER` names PseudonyMed's own data folder (a portable installation), the store lies there; `LEXCOR_DATA` overrides both. The store is shared, and another program may keep a whole terminology there (ICD-10-GM, SNOMED CT). PseudonyMed's categories are only the store's own lists, that is, those that came without an address (URL) of their own and got one from the store: the bundled lists, your own categories and what PseudonyMed's imports create. A terminology that brings an address of its own is not a category and is never changed by PseudonyMed, neither by an edit nor by a restored backup; it protects while it is ticked. Until November 2026 the vocabulary was a table of the pseudonym database; a database that still has that table hands its content over on first start. The store is then made to hold exactly the table's terms, the matcher's index is compared with the one the table gave, and only then is the table removed; if the comparison fails, the table stays and PseudonyMed says so instead of going on.

**Lists and terminologies: what protects and what is searched for.** Above the tables of *2 Identifiers* and *3 Medical vocabulary* the lists of the store are shown, each with a box to tick: in step 3 what is ticked protects its terms, in step 2 what is ticked is searched for. The ticks belong to the store, not to PseudonyMed: every program that reads the store applies the same, lexterm (which codes with the ticked lists of `lexterm.sqlite`) and lexident (which searches with those of `lexident.sqlite`) as well as PseudonyMed, and whoever sets them, the box here, the package window of lexterm or a command, sets them for all. On the command line `pseudonymed medical-terms lists|tick|untick` and `pseudonymed identifiers lists|tick|untick` show and set them (a list by its title or address), as do `lexterm packages list|on|off` and `lexident packages list|on|off`. A list is ticked when it comes into the store; *Take in a terminology …* takes one in applied at once, or, without the tick *apply at once*, unticked. It reads a FHIR CodeSystem or a FHIR package as the BfArM gives them out (ICD-10-GM and more), in step 3 also the Alpha-ID-SE of the BfArM (the ZIP file as downloaded), whose everyday wordings of diagnoses protect more than the official titles, and the unpacked folder of a SNOMED CT release (licensed: it stays in your store). A list another program brought is marked so; PseudonyMed never changes it, and *Take out a terminology* removes it (your own lists are edited in the table). *Where do terminologies come from?* says what there is, under which conditions, and where to download it, with the links (the same text as `lexterm sources`).

## Pseudonyms

The main person is `Patient K7Q4MX` (letters and digits from a keyed hash of name and date of birth, with a check character), relatives `Angehörige K7Q4MX-1`, referrers `Dr. Z1`, streets `[Straße …]`, towns `[Ort …]` and `[PLZ Ort …]`, the date of birth `[geb. 1959]` or `[Alter 66]`. Spelling variants of the same name give the same identifier; when a person only roughly resembles an existing entry, PseudonyMed asks. Details in `docs/pseudonyme.md`.

## Key capsules: pseudonyms for a recipient

Patients and colleagues can pseudonymise documents that one particular person, their physician say, is to read in clear later. The recipient publishes an OpenPGP public key (website, letterhead). The sender gives PseudonyMed that key in *9 Analysis* under *Recipient* (file or https address; *Check key* shows the fingerprint, which you compare with the recipient by a second channel; PseudonyMed pins it and warns when the key at the same address changes) and ticks *Pseudonymise for a recipient*. PseudonyMed then derives every pseudonym from a one-time key instead of its own secret, writes nothing to the local database, and puts the mapping back to the clear data, together with the patient's name, date of birth and identifier, into a capsule encrypted to the recipient: `name_pseudonym.capsule.asc`. The pseudonymised document and the language model's answer may be sent as usual; the capsule goes to the recipient only, never to the model.

The recipient opens the capsule in *13 Re-identification* (*Open capsule …*) with the private key: from the GnuPG keyring (the agent asks for the passphrase) or from a key file (*Private key*). Every pseudonym of the sender is then resolved, including relatives, referrers and places the recipient's own records never knew; the capsule's patient is matched against the local pseudonym store and the matching entry is named. Why a capsule rather than a pseudonym computed from the public key: a pseudonym anyone with the public key can recompute can be resolved by trying names and dates of birth; a random one-time key that only the recipient can unwrap reveals nothing.

Technology: the extra `pgp` brings pysequoia (Sequoia-PGP), bundled in the desktop app; an installed GnuPG is used when present. Curve25519 and RSA keys work; Curve25519 secret keys exported by GnuPG 2.5 are not yet read by pysequoia, use such keys through the keyring. Your own key without GnuPG: `pseudonymed keys create --name … --email …` (publish the public key, keep the private one safe; it has no passphrase). With GnuPG: publish `gpg --armor --export <key-id> > pseudonymed.asc` and the fingerprint from `gpg --fingerprint <key-id>`. `pseudonymed keys show FILE|ADDRESS` prints fingerprint and names of a key.

## Working state: variants of the same document

Preparation, text recognition and the review take time and judgement. *Save working state …* in the review keeps all of it: `name.working-state.<ending>` is the original as it came, byte for byte (for text files the text, `name.working-state.txt`, `.srt` …), `name.working-state.json` holds patient data, settings, docrepro's chain document (the configuration documents of typdoc, optdoc and ocrdoc: how the pages were bound and prepared, the filters, the words the OCR read with their boxes, the areas, the corrections), the hits with their pseudonyms, discarded hits, boxes, masks and take-ups. The original and the chain document give the prepared document and its reading again, byte for byte, so the hits lie on exactly the text they were found on. A working state of the format before docrepro (version 1) is no longer read; the message says so, and the original is prepared and reviewed again. Both files contain clear data; they belong where the original lies. Drop either of them on *4 Documents* and the review is back as saved, without another OCR run, steps 5 to 8 as they were left; the patient data is taken over. There you can decide differently (discard or restore hits, take up words), and *Analyse again* in *9 Analysis* searches the document with other settings (redact medications, NER off, say) while boxes, masks, take-ups and discarded hits stay. Every variant can be saved as a working state again. In recipient mode (one-time key) there is no working state, because the codes could not be restored. On the command line `--working-state` writes the state beside the output, and a `name.working-state.json` given as input is finished as saved, or, with `--reanalyse`, searched again with the options given.

## Command line

```sh
pseudonymed pseudonymise befund.pdf --contact "Müller 1959"
pseudonymed pseudonymise scan.pdf --patient patient.json --ocr tesseract --ner
pseudonymed pseudonymise gespraech.txt --contact "Müller 1959"               # transcript, fuzzy search on
pseudonymed pseudonymise gespraech.srt --patient patient.json --exact        # exact hits only
pseudonymed check befund_pseudonym.pdf --patient patient.json
pseudonymed reidentify brief.txt --code K7Q4MX --form salutation
pseudonymed pseudonymise foto.jpg --contact "Müller 1959" --clean-up off    # the photo read as it came
pseudonymed pseudonymise scan.pdf --patient patient.json --raw               # OCR text without Markdown
pseudonymed pseudonymise befund.pdf --patient me.json --recipient https://example.org/doctor.asc  # for a recipient
pseudonymed reidentify brief.txt --capsule befund_pseudonym.capsule.asc       # recipient, GnuPG keyring
pseudonymed keys create --name "Dr Example" --email doctor@example.org       # key pair without GnuPG
pseudonymed contacts local ~/Contacts/patients.vcf                           # local address book
pseudonymed contacts mac --on                                                # the Mac's Contacts app
pseudonymed contacts mac --address-book iCloud                               # only this address book
pseudonymed database location --database ~/Safe/pseudonymed.sqlite --key ~/Safe/key.txt
pseudonymed database status                                                  # statistics
pseudonymed database export ~/Backups                                        # asks for a passphrase
pseudonymed database import ~/Backups/pseudonymed_backup_2026-11-02_0900.zip.gpg
pseudonymed medical-terms merge befund_pseudonym.vocabulary.txt               # into your vocabulary
pseudonymed identifiers add "Musterwerk AG"                                  # an identifier of your own
pseudonymed identifiers check "arbeitet als Tischler"                        # what would be redacted?
pseudonymed pseudonymise brief.pdf --patient p.json --redact-doses --redact-measurements
pseudonymed pseudonymise brief.pdf --patient p.json --working-state          # writes brief.working-state.json + the original
pseudonymed pseudonymise brief.working-state.json --reanalyse --ner           # a variant from the working state
pseudonymed pseudonyms
pseudonymed config
```

Exit codes: 0 released, 1 input error, 2 not released, 3 pseudonyms left after re-identification, 4 uncertain match (`--same CODE` or `--new`).
