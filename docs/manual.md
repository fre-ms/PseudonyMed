# PseudonyMed – Manual

PseudonyMed redacts patient documents on your own computer before you hand them to a language model, and puts the clear data back afterwards. Nothing leaves the computer except the search in your own Nextcloud address book.

## Installation

**Packaged:** unpack the archive for your system (macOS: drag `PseudonyMed.app` to Applications; Windows and Linux: put the folder `PseudonyMed` anywhere). It contains the desktop interface `pseudonymed-gui` (macOS: the app) and the command line `pseudonymed`. The packages are not code-signed; macOS asks on first start (right-click, Open), Windows shows the SmartScreen notice.

**From source:** Python 3.12 or newer and [uv](https://docs.astral.sh/uv/), then

```sh
uv sync --extra ocr --extra codes --extra gui
uv run pseudonymed gui --language en
```

Tesseract is used as a second OCR engine when it is installed (macOS: `brew install tesseract tesseract-lang`, Ubuntu: `apt install tesseract-ocr tesseract-ocr-deu`); it is found in the usual places even when the app is started from the Finder. It is not required, RapidOCR is included. To prefer Tesseract, put `backend = "tesseract"` under `[ocr]` in the configuration file (`pseudonymed config` shows the path) or set `PSEUDONYMED_OCR=tesseract`.

**Language.** The interface follows the system language; `--language en` or `--language de` on the command line, the menu *Language* in the window, or `PSEUDONYMED_SPRACHE=en` choose it explicitly. The command line follows the same setting (`pseudonymed --language en <command>`, `PSEUDONYMED_SPRACHE`, `[gui] sprache`, else `LANG`). In English every message, every help text, the control step and the reports (`.bericht.json`, the vocabulary file) are English; commands and options have a German and an English name, and both work in either language, so that scripts run anywhere (`pseudonymise` or `pseudonymisieren`, `database status` or `datenbank status`, `--target` or `--ziel`); the help lists the commands under the names of its language and shows each option's two names, its language's first. The words an option takes as its value come in German and in English too (`year` or `jahr`, `age` or `alter`, `off` or `aus`, `replace` or `ersetzen` …), and both work in either language; the help names those of its language. Pseudonyms such as `[geb. 1959]` or `[Ort …]` stay German in either language, because they are part of the German document.

## First start

PseudonyMed creates the pseudonym database (`pseudonyme.sqlite`) and the secret key next to it (`pseudonymschluessel.txt`) in the user data folder; `pseudonymed config` shows the paths. **Back up the key.** With the same key every computer produces the same pseudonyms; without it old identifiers cannot be reproduced. The database holds the mapping pseudonym → clear data for re-identification; it is patient data and stays on the computer. `PSEUDONYMED_DATENORDNER` puts database, key and configuration into one folder, for a portable installation on an encrypted stick.

Set up the address book once (command line):

```sh
pseudonymed contacts setup --url https://your-nextcloud.example --user yourname --address-book patients
```

The app password (Nextcloud → Settings → Security) goes into the operating system's keyring.

## The eleven steps

1. **Patient data.** Search the address book (name, year of birth), load a patient file or a vCard. Address books are set up under *Set up address books …*: a local vCard file or a folder of vCard files (exported from Apple Contacts, Thunderbird, Outlook or Nextcloud; stays on the machine) and/or Nextcloud over CardDAV (address, user, app password from Nextcloud → Security; the password goes into the keyring, or into the configuration file where there is no keyring). Hits appear in a list that shows only when there are hits; a click fills the fields. *Patient file …* loads a JSON or TOML file with the identifiers as `pseudonymed contacts export` writes them; *Save template …* gives an empty one to fill in. Check the fields: everything listed there will be redacted. Add relatives, referrers and further terms (one per line) or drop a text file with one entry per line onto the field; they are not taken from a contact's notes automatically. *Use this patient*.
2. **Identifiers.** What leads to a person besides the patient data without being medical: hospitals (hospital directories of Germany and Switzerland, Austria on request in *11 Database*), occupations (German classification of occupations 2010), study acronyms (ClinicalTrials.gov, DRKS), titles and your own entries (employers, clubs, institutions; class *Sonstiges*). The table works like the medical vocabulary: search, filter by class, edit cells, add, delete, export and import CSV. Like the patient data, identifiers are redacted by default (placeholders such as `[Klinik 7HQ2NB]`, `[Beruf …]`, dashed in the visual review and discardable), but only in context: hospital names wherever they stand (the official name, its main part, or *Klinikum, Krankenhaus … + town* for towns with a hospital), occupations only next to cues such as *arbeitet als*, *gelernter*, *ist*, *von Beruf* or in the social history, study acronyms only in the registered spelling next to *Studie* (registry numbers such as NCT or DRKS always), titles only directly before or after a name that was found, your own entries everywhere. Every listed spelling of an entry is looked for. Where a place fits more than one class (an acronym of a study that is also an occupation, say), it is redacted once and named after the first of hospital, occupation, study, a class of your own, *Sonstiges*. Employment status (retired, unemployed) stays, following the GeMTeX guideline. Deleted bundled entries stay deleted across updates until you restore them; changed ones become your own. The entries are not in the pseudonym database: they live in `lexident.sqlite`, the store of lexident, the library that recognises such identifiers, beside the store of the vocabulary (`pseudonymed identifiers status` shows the path). Every list is a package there, your own entries are lists called *Nutzer: class*, and what you deleted is hidden, not removed. As with the vocabulary, only the store's own lists are PseudonyMed's: a directory another program keeps there under an address of its own is neither shown nor looked for nor changed. A database that still holds the identifiers of an earlier version hands them over on first start, checked entry by entry before its tables go. The box in *6 Analysis* switches the redaction off.
3. **Medical vocabulary.** Every term NER and the fuzzy search must never redact, as a sortable table (term, category) over the store of lexterm, the library that keeps medical terms: the bundled lists (medicine from Wikidata, body parts, findings terms, eponyms) are installed there on first start, each category as a package of its own. Search, sort by column (header), change cells by double click, add and delete terms (bundled ones too, "Wolf" say), export CSV and import CSV or lists (one term per line, for instance the `.vokabular.txt` written on export). A deleted term is hidden in the store rather than taken out of its list, so it stays away when the list is installed again; *Load the bundled lists again* brings deleted base terms back. Command line: `pseudonymed medical-terms status|add|remove|export|import|merge`.
4. **Documents.** Drop PDFs, photos or text files (`.txt`, `.md`, `.srt`, `.vtt`, Whisper `.json`, `.eml`, for instance the transcript of a recorded consultation or a patient's e-mail); they are opened at once. A working state saved in the review (`name.arbeitsstand.json`, or the document `name.arbeitsstand.pdf` beside it) fills everything in again up to and including *7 Visual review*: patient data, clean-up, text recognition with its corrections, hits, discarded hits, boxes, masks and take-ups; the window goes straight to the review. Photos and images go on a sheet of the chosen paper size (A4, A5, A3, US Letter, US Legal or "as large as the image"; portrait or landscape follows the image, which is scaled to fit). Pages without a text layer (scans, photos) appear underneath for the clean-up before text recognition, each with a suggestion: straighten the tilt (suggested from 1.2°, angle adjustable), unwarp a photographed sheet, upscale 2×, 3× or 4× (the OCR reads the page at that multiple of the resolution; the page itself is not stored enlarged), letter mode (Lanczos enlargement and sharpened strokes in grey scale; a hard black-and-white threshold lowered the recognition markedly in measurements, so it is never suggested automatically), even out the background, black and white, and under *Further steps*: clean dark borders, remove coloured ink (stamps, highlighter, blue signatures), denoise, raise contrast, sharpen, remove lines, detect orientation (portrait/landscape from the lines, upside-down by a short OCR comparison), rotate in 90° steps. Rectangles drawn on the "after" image erase the region white before the OCR sees it (*Restore erased areas* undoes that). Denoising, contrast and sharpening have strength sliders; erased areas can be taken back one by one with Cmd/Ctrl+Z. Original on the left, result on the right with a movable divider, both views linked when panning (Shift or Option + drag, middle button) and zooming; an upscaled result is shown at the original size, zooming in reveals the gain. *Apply steps to all pages* copies the switches. A learnt super-resolution model for text is not included; it would need extra libraries and models. *Next: analyse*.
5. **Text recognition.** Choose the OCR engine (RapidOCR with bundled models, Tesseract, off) and the language packs (Tesseract: `deu+eng`, the installed languages are listed; RapidOCR: language type `de`, `en`, `latin`). Tesseract takes a bordered table for graphics and skips the cells (a medication table came back as a single word); PseudonyMed therefore looks for grids on every page, cuts them out, removes the rules and reads the crop in a second pass as one block; the better reading wins. Measured on synthetic tables with thick borders: 0 of 45 cell words without, 42 with the second pass; pages without a grid are untouched. The *Tables* checkbox switches it off. RapidOCR does not have the problem. With *Structure the recognised text* (on by default) the recognised text appears as Markdown: lines that run to the right margin are joined into paragraphs (hyphenation undone), a taller gap ends the paragraph, lines in a larger face become headings, short bold lines on their own small headings, bullets list items, words far apart table cells (several such lines a Markdown table). Italics are not recognised; the engines report no slant. The structure is computed from the geometry of the OCR lines and applies to the text file, the Markdown and the editor; you correct the structured text. Independently of that, the invisible text layer of the PDF sits word by word on the image words: for corrected or structured text every word is aligned to the OCR word it came from (a corrected word takes the box of the one it replaces, inserted words sit between their neighbours, Markdown characters get no box), so that text can be selected in a PDF reader exactly where it is printed. *Start text recognition* reads all documents on the basis of the cleaned-up pages. Then every page shows the cleaned-up image next to the recognised text, which you correct by hand on OCR pages (*Apply text*); text from a text layer cannot be changed. The correction feeds the text file, the Markdown and the invisible text layer; what the OCR misread in the image you redact later with a box or a mask. *Next: analyse*.
6. **Analysis.** *Analyse* searches new documents, *Analyse again* also those analysed already, with the current settings: clean-up, text recognition and corrections stay, boxes, masks, take-ups and discarded hits are taken over. That is how variants of the same document come about without starting over. The detection settings: form of the date of birth, barcodes, unreadable lines, medical terms, fuzzy search in text files (speech recognition misspells names the way OCR does), NER, and four options for the medical content, all off by default because medications and lab values belong to the content: *Medikamente: Substanz schwärzen* replaces the drug name from the lexicon by `[Medikament …]` (names that also denote a disease, such as *ASS*, stay); *Medikamente: Dosierung und Verordnungsschema schwärzen* replaces what stands next to a substance by `[Dosierung …]` (*500 mg 1-0-1*, *2 Tbl.*, *bei Bedarf*, *p. o.*), the substance stays unless chosen separately; *Laborwerte: Untersuchung schwärzen* replaces the name of the examination wherever it stands by `[Laborwert …]`; *Laborwerte: Messwert schwärzen* replaces the value after an examination by `[Messwert …]` (*2,3 mU/l*, *< 5 mg/l*). The four levels are independent: knowing the substance is one thing, knowing dose and schedule another; knowing what was examined is one thing, the value another. A term on both lists (*Kalium*) is a lab value when a measurement follows and a medication when a dose follows. Trade names the lexicon does not know (Marcumar, say) go into *3 Medical vocabulary* with the category *Medikament*, your own lab names with the category *Laborwert*. The re-identification puts everything back. Below it the statistics of the medical vocabulary (edited in *3 Medical vocabulary*) and *Recipient*: whoever pseudonymises for someone else (see key capsules) gives that person's public key here. Defaults: mark and protect medical terms, then NER (if the extra is installed). Below it the medical vocabulary with its sources and *Import vocabulary …*: a text file with one term per line, for instance the `.vokabular.txt` written on export, is merged into your own vocabulary and protected from the next analysis on. *Analyse* searches all read documents with a progress bar; the review step opens afterwards.
7. **Visual review.** Redaction only now; the text is no longer edited here. Traffic-light colours: red will be redacted (dashed when NER or the fuzzy search merely suggest it), yellow was read with low confidence by the OCR (unreadable lines are blanked as a precaution), green stays: medical terms and discarded hits, which remain visible and can be restored with a click. The source of every hit is in the table. A false hit (a drug name that looks like a surname): click it, *Discard hit*. Dragging draws a box with the replacement text from the field next to the buttons; with *Draw mask* a black mask under which text and image disappear; Shift + drag pans the view, Ctrl/Cmd + wheel zooms. *Remember discarded hits for this patient* stores your decisions in the pseudonym store on export: in the next document of the same patient the same text under the same rule starts out green and can be restored. What the OCR misread in the image you redact with a box or a mask; the text itself is corrected in the text-recognition step. Something missed, a handwritten name for instance: drag a box over it. Zoom with Ctrl/Cmd and the wheel or the buttons. Something the analysis did not find, or a medical term that stays green, gets into the list with a click on the word (blue) and *Take up selection*; Ctrl/Cmd + click extends the selection to the clicked word. With the default *[geschwärzt]* left in the replacement field, a word taken up gets a code of its own, `[Begriff …]`, which the re-identification puts back; otherwise the text entered. *Save working state …* writes the prepared document (`name.arbeitsstand.pdf`) and a configuration file (`name.arbeitsstand.json`) with everything made so far; both contain clear data and are kept like the original. Dropped on *4 Documents* again, the review can be resumed or varied. A text file appears as text with coloured spans instead of a page image; click a span to select the hit, select text and press *Take up selection* to turn it into a manual hit. Orange spans are the fuzzy search's hits: suggestions worth a look.
8. **Control.** Two lights before the export. The first is the re-check: the complete finishing phase runs into a scratch folder and the result is searched for everything from *1 Patient data*; red means something was still found, so rework. The second is the residual risk: an estimate of how many people share what the text still says. It follows the k-map idea of disclosure-risk assessment (El Emam, EMA Policy 0070 with its threshold of 0.09, Rocher et al. 2019): sex (1 bit), year of birth or age (about 6.4 bits), the smallest named place by population (Destatis municipality directory) and the rarest named rare disease by Orphanet prevalence are converted into bits; about 26.3 bits single one person out of Germany. λ is the expected number of people sharing the details, κ the chance that a match is the right person. Green from λ = 11 (κ ≤ 0.09), yellow from 5, red below. Flags name what the model cannot weigh: ages from 90, year of birth and age next to exact dates, dated reportable events, occupation, family details, places under 20,000 inhabitants. All documents of the same patient are judged together, released ones included (only categories and weights are remembered, never clear text). Reference population (Germany or the catchment area of the consultation service) and own places (consultation service, clinic) are settings. The estimate is a synthesis of published parts, not a standard, and assumes independent attributes, which is optimistic for atypical combinations; it points the review to the detail with the largest contribution. Red does not block the export but requires an explicit confirmation.
9. **Export.** The lights of *8 Control* (re-check and residual risk) appear here again; whoever skipped that step gets the re-check on opening. The first light shows the outcome: green means nothing found any more, ready to export; yellow means released but with warnings you should read; red means data were still found, the export button stays off and a message names the leftovers, which you rework in the review step with a box or a mask. The export then copies the checked files. The report records what was searched again ("Erneut geprüft nach dem Prüfschritt: …") and which hits you kept on purpose; your deliberate decisions and general reminders (clean-up steps, OCR summary, the note that handwriting is not read, blanked unreadable lines, NER counts, fuzzy hits, remembered discards) are listed under *Hinweise*, only what needs attention under *Warnungen* (pages without OCR, NER requested but missing, an uncertain patient match, a failed re-check), and only those turn the light yellow; a passed scan is green. With *Vocabulary of the discarded guesses* (on by default) you also get `name_pseudonym.vokabular.txt`: the NER and fuzzy hits you discarded in the review, one term per line, for the import in *3 Medical vocabulary*; discarded hits of the fixed rules are left out, their text being one of the patient's identifiers. Choose a target folder. Per document you get `name_pseudonym.pdf` (with a text layer: for scans and photos the OCR text minus the hits is embedded invisibly, also after *rasterise completely*), `name_pseudonym.txt` (the text in reading order, this is what you give the language model), optionally `name_pseudonym.md`, and `name_pseudonym.bericht.json`; a text file yields only `name_pseudonym.txt` (same extension as the input, subtitle timestamps preserved) and the report. The re-check reads the result again; if an identifier survives, nothing is released and the report says why. OCR pages get preview images: look at them before you pass a scan on.
10. **Re-identification.** Paste the language model's text, pick the person, *Re-identify*. If the text comes from someone else, open their key capsule (*Open capsule …*, see below); its mapping then replaces the local database.
11. **Database.** Where database and key file live (any folders, even apart; a change copies the current files there and renames the old ones), statistics of the pseudonym store (patients, mappings per category, remembered discards, size, integrity, key handle) and backup and restore of everything re-identification needs: database and key file, the identifiers, optionally configuration and vocabulary (vocabulary and identifiers are not in the database; the vocabulary travels in the archive as a CSV, the identifiers as a store that holds PseudonyMed's lists and nothing another program keeps beside them). The backup is a ZIP with checksums, encrypted with a passphrase (`.zip.gpg`, `gpg --decrypt` opens it too) or, if you insist, plain. Restoring replaces database and key (the current ones are set aside) or merges an archive made with the same key; two different keys cannot be mixed. The vocabulary follows: restoring makes it exactly what the archive holds, merging adds what is new, and without the box it stays as it is. So do the identifiers: restoring makes the lists exactly those of the archive (yours are copied aside first, like database and key), merging adds those of your own entries that are new. Nothing is imported while analysed documents are still waiting for export. Under *Additional data*, *Fetch from the ministry* loads the current list of Austrian hospitals straight from the ministry of health into the store of the identifiers on your computer (or *From file …* a workbook you downloaded yourself); PseudonyMed does not bundle it because the ministry permits reprinting only for non-commercial purposes. Command line: `pseudonymed database status|export|import|extra-data hospitals-at`. *Mr/Ms surname* inserts the salutation by grammatical case, *full name* the name. Mangled pseudonyms (wrong check character) are reported with a suggestion.

## Texts and transcripts

If you record consultations and transcribe them locally, the transcript is a text file: it runs through the same detection as a PDF, and the result is text again with pseudonyms and nothing else changed. Particulars: the fuzzy search finds the patient's name even when misspelt ("Flanz" for "Flantz") but requires a capital letter for names and places; at the start of a sentence it may suggest similar words ("Land" for Lang), which you discard in the review step. `--exact` switches it off. Numbers spoken as words are read as digits before matching: "am einundzwanzigsten Juli neunzehnhundertneunundfünfzig" is the date of birth, "Sieringgasse zweiundvierzig" the street, "acht zwei vier sechs zwei" the postcode; the whole phrase is then replaced.

**Whisper JSON** (openai-whisper, whisper.cpp, WhisperX) is rendered as one line per segment with timestamp and speaker and written as `.txt`; word timings and token ids are not carried over, because the token ids hold the clear text in another form. **E-mails** (`.eml`, dragged or exported from the mail program) become From, To, Cc, Date, Subject, the body (from HTML if need be) and a list of attachment names; routing headers such as Message-ID are left out and attachments are not included: pseudonymise an attached PDF or photo as a file of its own.

## What is redacted and what is not

Redacted: the name in all spellings, the date of birth in all formats, address, telephone, e-mail, insurance number, patient ID, file numbers, the relatives and referrers you entered, barcodes, and generically every insurance number, IBAN and e-mail address as well as values behind labels such as "Versicherten-Nr." or "Pat.-ID". With NER switched on, additionally people and places the model recognises.

Redacted by default but discardable in the visual review: identifiers from *2 Identifiers* (hospitals, occupations in context, studies, titles next to names).

Not redacted: diagnoses, medications and lab values (on request in four levels: substance, dose, examination, measurement; see *6 Analysis*), measurements, findings, appointment dates, employment status. Not recognised: unknown names when NER is off, and handwriting the OCR does not detect as text; the review step is there for that.

## NER

Named-entity recognition is a statistical model (spaCy, trained on German news) that tags person and place names in free text without a list. It catches the relative or colleague nobody entered, but it guesses: it may tag a drug or a department as a person, and it may miss a name. Therefore its hits are shown in their own colour in the review step, medical eponyms (Alzheimer, Parkinson, Babinski …) and everything the medical vocabulary marks are excluded, ordinary words that are only capitalised because they start a sentence ("Überwiesen hat Sie …") are dropped, and it never decides about the release. The graphical interface runs it by default once the extra is installed, after the vocabulary has marked the page; on the command line it stays opt-in (`--ner`). Install with

```sh
uv sync --extra ner
uv pip install https://github.com/explosion/spacy-models/releases/download/de_core_news_md-3.8.0/de_core_news_md-3.8.0-py3-none-any.whl
```

People it finds become `Person <code>`, places `[Ort <code>]`, with the same keyed hash as the patient's identifier, so the same name gets the same code and the re-identification knows it.

## Medical vocabulary: what guesswork must never touch

NER and the fuzzy OCR search run behind a guard: before they look at a page, every medical term on it is marked, and those spans are off limits to both. The deterministic rules for the patient's own identifiers are unaffected (a patient really called Herz is still redacted). The bundled base vocabulary (about 40 000 German terms) comes from Wikidata (CC0): German labels and synonyms of every item with an ICD-10 code, an ATC code, an INN or a MeSH descriptor in the medical MeSH trees (anatomy, organisms, diseases, drugs, techniques, psychiatry, phenomena); geography and occupations are excluded so that towns and surnames remain recognisable. Inflection, hyphenated compounds (*Parkinson-Syndrom*) and umlaut transliteration are recognised, multi-word terms as a whole.

A second bundled list (`koerperteile_de.txt`, about 580 entries) covers body parts, organs, bones, muscles, vessels and nerves in everyday German plus side and position words (links, rechts, proximal …), because the Wikidata list lacks many colloquial forms (Kopf, Nacken, Oberbauch, Wade) and NER liked to take them for names. A third list (`befundbegriffe_de.txt`, about 370 entries) holds the terms of the clinical examination and the findings report as they head the lines of a status (Konzentration, Haltung, Gangbild, Strichgang, Nierenlager, Reflexe, Sensibilität, Procedere …), which are in neither MeSH nor the body-part list. On the order: the vocabulary marks the page first, then NER runs and skips every entity inside a marked span; NER also drops single words the tagger calls common nouns and unknown single words (compounds such as *Nierenlager*) without a salutation, title or preposition before them.

Your own vocabulary grows with every review: the export writes the discarded guesses to `name_pseudonym.vokabular.txt`, and *Import CSV or list …* in *3 Medical vocabulary* or `pseudonymed medical-terms merge FILE` takes such a file into the vocabulary (category “Nutzervokabular”). The vocabulary shields terms from NER and the fuzzy search for every patient; for hits of the fixed rules there is the *Remember discarded hits for this patient* box in the review step.

Your own lists: `pseudonymed medical-terms import FILE --name CATEGORY` from MeSH XML (`--format mesh-xml`, the NLM file or a translation), from ICD-10-GM, Alpha-ID-SE or ATC tables (`--format csv --column N`) or from any plain list (one term per line); everything lands in lexterm's store, beside the bundled lists, and a backup takes it along. `pseudonymed medical-terms check WORD` tells whether a word is protected, `pseudonymed medical-terms status` lists the categories. SNOMED CT cannot be shipped (a BfArM licence is required); a locally licensed description file imports like any CSV.

Where the vocabulary lives: in `lexterm.sqlite`, the store of the library lexterm, in the data folder of the lex libraries (macOS `~/Library/Application Support/lexcor`, Windows `%APPDATA%\lexcor`, Linux `~/.local/share/lexcor`), where other programs that use lexterm find it; `pseudonymed medical-terms status` shows the path. When `PSEUDONYMED_DATENORDNER` names PseudonyMed's own data folder (a portable installation), the store lies there; `LEXCOR_DATA` overrides both. The store is shared, and another program may keep a whole terminology there (ICD-10-GM, SNOMED CT). PseudonyMed's categories are only the store's own lists, that is, those that came without an address (URL) of their own and got one from the store: the bundled lists, your own categories and what PseudonyMed's imports create. A terminology that brings an address of its own is not a category, protects nothing and is never changed by PseudonyMed, neither by an edit nor by a restored backup. Until November 2026 the vocabulary was a table of the pseudonym database; a database that still has that table hands its content over on first start. The store is then made to hold exactly the table's terms, the matcher's index is compared with the one the table gave, and only then is the table removed; if the comparison fails, the table stays and PseudonyMed says so instead of going on.

## Pseudonyms

The main person is `Patient K7Q4MX` (letters and digits from a keyed hash of name and date of birth, with a check character), relatives `Angehörige K7Q4MX-1`, referrers `Dr. Z1`, streets `[Straße …]`, towns `[Ort …]` and `[PLZ Ort …]`, the date of birth `[geb. 1959]` or `[Alter 66]`. Spelling variants of the same name give the same identifier; when a person only roughly resembles an existing entry, PseudonyMed asks. Details in `docs/pseudonyme.md`.

## Key capsules: pseudonyms for a recipient

Patients and colleagues can pseudonymise documents that one particular person, their physician say, is to read in clear later. The recipient publishes an OpenPGP public key (website, letterhead). The sender gives PseudonyMed that key in *6 Analyse* under *Recipient* (file or https address; *Check key* shows the fingerprint, which you compare with the recipient by a second channel; PseudonyMed pins it and warns when the key at the same address changes) and ticks *Pseudonymise for a recipient*. PseudonyMed then derives every pseudonym from a one-time key instead of its own secret, writes nothing to the local database, and puts the mapping back to the clear data, together with the patient's name, date of birth and identifier, into a capsule encrypted to the recipient: `name_pseudonym.kapsel.asc`. The pseudonymised document and the language model's answer may be sent as usual; the capsule goes to the recipient only, never to the model.

The recipient opens the capsule in *10 Re-identification* (*Open capsule …*) with the private key: from the GnuPG keyring (the agent asks for the passphrase) or from a key file (*Private key*). Every pseudonym of the sender is then resolved, including relatives, referrers and places the recipient's own records never knew; the capsule's patient is matched against the local pseudonym store and the matching entry is named. Why a capsule rather than a pseudonym computed from the public key: a pseudonym anyone with the public key can recompute can be resolved by trying names and dates of birth; a random one-time key that only the recipient can unwrap reveals nothing.

Technology: the extra `pgp` brings pysequoia (Sequoia-PGP), bundled in the desktop app; an installed GnuPG is used when present. Curve25519 and RSA keys work; Curve25519 secret keys exported by GnuPG 2.5 are not yet read by pysequoia, use such keys through the keyring. Your own key without GnuPG: `pseudonymed keys create --name … --email …` (publish the public key, keep the private one safe; it has no passphrase). With GnuPG: publish `gpg --armor --export <key-id> > pseudonymed.asc` and the fingerprint from `gpg --fingerprint <key-id>`. `pseudonymed keys show FILE|ADDRESS` prints fingerprint and names of a key.

## Working state: variants of the same document

Clean-up, text recognition and the review take time and judgement. *Save working state …* in the review keeps all of it: `name.arbeitsstand.pdf` is the prepared document in clear text (for text files `name.arbeitsstand.txt`, `.srt` …), `name.arbeitsstand.json` holds patient data, settings, the clean-up plan, every page with its text layer and OCR words and boxes, the corrected OCR text, the hits with their pseudonyms, discarded hits, boxes, masks and take-ups. Both files contain clear data; they belong where the original lies. Drop either of them on *4 Documents* and the review is back as saved, without another OCR run; the patient data is taken over. There you can decide differently (discard or restore hits, take up words), and *Analyse again* in *6 Analysis* searches the document with other settings (redact medications, NER off, say) while boxes, masks, take-ups and discarded hits stay. Every variant can be saved as a working state again. In recipient mode (one-time key) there is no working state, because the codes could not be restored. On the command line `--working-state` writes the state beside the output, and a `name.arbeitsstand.json` given as input is finished as saved, or, with `--reanalyse`, searched again with the options given.

## Command line

```sh
pseudonymed pseudonymise befund.pdf --contact "Müller 1959"
pseudonymed pseudonymise scan.pdf --patient patient.json --ocr tesseract --ner
pseudonymed pseudonymise gespraech.txt --contact "Müller 1959"               # transcript, fuzzy search on
pseudonymed pseudonymise gespraech.srt --patient patient.json --exact        # exact hits only
pseudonymed check befund_pseudonym.pdf --patient patient.json
pseudonymed reidentify brief.txt --code K7Q4MX --form salutation
pseudonymed pseudonymise foto.jpg --contact "Müller 1959" --paper letter     # image on US Letter
pseudonymed pseudonymise scan.pdf --patient patient.json --raw               # OCR text without Markdown
pseudonymed pseudonymise befund.pdf --patient me.json --recipient https://example.org/doctor.asc  # for a recipient
pseudonymed reidentify brief.txt --capsule befund_pseudonym.kapsel.asc       # recipient, GnuPG keyring
pseudonymed keys create --name "Dr Example" --email doctor@example.org       # key pair without GnuPG
pseudonymed contacts local ~/Contacts/patients.vcf                           # local address book
pseudonymed database location --database ~/Safe/pseudonymed.sqlite --key ~/Safe/key.txt
pseudonymed database status                                                  # statistics
pseudonymed database export ~/Backups                                        # asks for a passphrase
pseudonymed database import ~/Backups/pseudonymed_sicherung_2026-11-02_0900.zip.gpg
pseudonymed medical-terms merge befund_pseudonym.vokabular.txt               # into your vocabulary
pseudonymed identifiers add "Musterwerk AG"                                  # an identifier of your own
pseudonymed identifiers check "arbeitet als Tischler"                        # what would be redacted?
pseudonymed pseudonymise brief.pdf --patient p.json --redact-doses --redact-measurements
pseudonymed pseudonymise brief.pdf --patient p.json --working-state          # writes brief.arbeitsstand.pdf + .json
pseudonymed pseudonymise brief.arbeitsstand.json --reanalyse --ner           # a variant from the working state
pseudonymed pseudonyms
pseudonymed config
```

Exit codes: 0 released, 1 input error, 2 not released, 3 pseudonyms left after re-identification, 4 uncertain match (`--same CODE` or `--new`).
