# PseudonyMed

[![Tests](https://github.com/fre-ms/PseudonyMed/actions/workflows/tests.yml/badge.svg)](https://github.com/fre-ms/PseudonyMed/actions/workflows/tests.yml)

Local pseudonymisation of patient documents (PDF, scans, photos, transcripts) so that they can be handed to cloud language models for drafting letters. Identifiers are replaced by **stable pseudonyms** rather than black bars, so the text stays readable and consistent for the model; afterwards the clear data is put back locally. The pseudonym key never leaves the machine.

**Name.** Until 3 November 2026 this project was called AnonyMed. The new name says what it does: the output is pseudonymised, not anonymous, because the key that maps the pseudonyms back stays with you (see `docs/trademark-search-2026-11-03.md` for the name check). *AnonyMed* is now the working title of a planned downstream program for a separate recipient that receives only pseudonymised texts, never keys or mapping, searches them a second time independently and replaces the codes with its own, much like a trust centre. Existing installations keep their data: the data folder of the old name is moved on first start, `ANONYMED_*` environment variables still work, old key capsules and backups are read, and `anonymisieren` remains a hidden alias of `pseudonymisieren`.

Status (31 October 2026): milestones M0 (core), M1 (command line), M2 (CardDAV address book), M3 (scans, photos, OCR, barcodes) and M4 (desktop interface) are done. Installers (M5) follow. The design, open decisions and milestones are kept in the project's internal hand-over notes.

## The round trip

1. The patient's identifiers (name, date of birth, address, phone, e-mail, insurance number, relatives, referring physicians, file numbers) come from the CardDAV address book of your Nextcloud, a local vCard file or a patient file.
2. Every occurrence in the document is removed from the PDF content stream (real redaction with PyMuPDF) and the pseudonym is written into the gap: `Patient K7Q4MX`, `[geb. 1959]`, `[Straße 7HQ2NB]`, `[PLZ Ort 2F7QV4]`, `Angehörige K7Q4MX-1`, `Dr. Z1` … Streets and towns get their own codes from the same keyed hash of their phonetic form, so *Musterstr. 12* and *Musterstraße 12*, *München* and *Muenchen* always map to the same code. The identifier is a keyed hash of the phonetically normalised name and the date of birth, so the same person gets the same code on every machine that holds the key, and spelling variants do not matter; an error-tolerant record linkage in the manner of the Mainzelliste recognises people already in the local store (see `docs/pseudonyme.md`).
3. Metadata, XMP, bookmarks, annotations, form fields and attachments are stripped.
4. The result is re-read and checked against the same rules; nothing is released if a single identifier survives.
5. The language model writes the letter using the pseudonyms.
6. `pseudonymed rueckersetzen` puts the clear data back, including German case forms ("Patient K7Q4MX" → "Herr X", "Patienten K7Q4MX" → "Herrn X"), and flags codes the model mangled (check character).

## Install

**Packaged:** unpack the archive for your system (macOS: `PseudonyMed.app`; Windows and Linux: the folder `PseudonyMed` with `pseudonymed-gui` and the command line `pseudonymed`). The packages are built by `packaging/build.py` with PyInstaller and are not code-signed yet; macOS asks on first start (right-click, Open). Manuals: `docs/anleitung.md` (German), `docs/manual.md` (English).

**From source:** Python 3.12 or newer and [uv](https://docs.astral.sh/uv/).

```sh
git clone <repository> PseudonyMed
cd PseudonyMed
uv sync --extra ocr --extra codes --extra gui
uv run pseudonymed --help
```

On first start PseudonyMed creates the pseudonym database and the secret key in the user data folder (`pseudonymed konfig` shows where; `PSEUDONYMED_DATENORDNER` overrides the folder, for a portable installation on an encrypted stick for instance). Back the key up.

## Usage

```sh
# 1. say who the patient is: address book, vCard file or patient file
uv run pseudonymed kontakte einrichten --url https://cloud.example.org --benutzer dr   # once; asks for an app password
uv run pseudonymed kontakte suchen "Müller 1959"                                        # name parts, year or date of birth
uv run pseudonymed kontakte zeigen "Müller 1959"                                        # what will be redacted
uv run pseudonymed kontakte export "Müller 1959" -o patient.json                        # to add relatives, referrers, terms
uv run pseudonymed vorlage > patient.json                                               # or write the file from scratch

# 2. pseudonymise one or more files
uv run pseudonymed pseudonymisieren befund.pdf --kontakt "Müller 1959"      # straight from the address book
uv run pseudonymed pseudonymisieren befund.pdf --vcf export.vcf --nr 2      # from a vCard file
uv run pseudonymed pseudonymisieren befund.pdf --patient patient.json       # from a patient file
#    -> befund_pseudonym.pdf          redacted PDF with text layer, pseudonyms in place, metadata removed
#    -> befund_pseudonym.md           optional Markdown (--markdown)
#    -> befund_pseudonym.txt          text in reading order (paste this into the model)
#    -> befund_pseudonym.bericht.json audit report without any clear data

# 3. check any file again
uv run pseudonymed pruefen befund_pseudonym.pdf --patient patient.json

# 4. put the clear data back into the model's answer
uv run pseudonymed rueckersetzen brief.txt --kennung K7Q4MX --form anrede

# housekeeping
uv run pseudonymed pseudonyme        # which identifier belongs to whom, with linked spellings (local only)
uv run pseudonymed konfig            # version, pseudonym database and key file (back the key up!)
```

Options of `pseudonymisieren`: `--datum alter` writes `[Alter 36]` instead of `[geb. 1990]`; `--rastern` produces an image-only PDF; `--ocr auto|rapidocr|tesseract|aus`; `--keine-tabellen` (no table pass with Tesseract); `--roh` (OCR text as plain lines instead of Markdown); `--papier a4|a5|a3|letter|legal|bild` (sheet for images); `--kein-vokabular`; `--empfaenger KEY` (one-time pseudonyms and an encrypted key capsule for a recipient); `--keine-codes`; `--vorschau auto|immer|nie`; `--kein-text`, `--kein-bericht`, `--ohne-vermerk`; `--ziel DIR`; `--speicher FILE` for a different pseudonym database; `--konfig FILE` for a different configuration file.

### Desktop interface

Eleven steps as tabs: patient; identifiers (hospitals, occupations, study acronyms, titles and your own entries, redacted by default with a context rule per class); vocabulary (the protected terms as a sortable, editable table of the database: add, delete, CSV in and out); documents (files are opened as soon as they are dropped, photos and images go on a sheet of the chosen paper size, A4 by default, and scans and photos appear underneath for the clean-up before OCR); text recognition (engine and language packs, Tesseract's table pass, then the recognised text next to the cleaned-up page, correctable by hand before anything is searched); analysis (the detection settings, with progress, and the import of your own vocabulary); review (redaction only, the text is no longer edited there); control (re-check and residual-risk estimate); export; re-identify; database (statistics, backup and restore of database and key). Every step sits in a scroll area, so the window can be made as small as you like. Entering the export step runs the whole finishing phase into a scratch folder first, including the re-check with the patient's identifiers, and shows a traffic light: green means nothing was found and the export is ready, yellow means released but with warnings to read, red means identifiers from step 1 are still there, the export button stays off and a warning names the leftovers. The export then copies the checked files. The report states what was searched again ("Erneut geprüft nach dem Prüfschritt: Name, Geburtsdatum, …") and which hits were kept on purpose; what was done on purpose (the clean-up steps, the OCR summary, the general reminder that handwriting is not read, blanked unreadable lines, NER counts, fuzzy hits, remembered discards) is listed under *Hinweise*, and only what needs attention under *Warnungen* (pages without OCR, NER requested but missing, an uncertain patient match, a failed re-check), which alone turn the light yellow; a passed re-check on a plain scan is green. Alongside the files the export writes `<name>_pseudonym.vokabular.txt`, the discarded guesses (NER, fuzzy search) one per line, which the vocabulary step imports into the table (see below). The review uses traffic-light colours: red is everything that will be redacted (dashed when NER or the fuzzy search merely suggest it), yellow is text the OCR read with low confidence (unreadable lines are blanked as a precaution), green is what stays: protected medical terms and hits you discarded, which remain visible and can be restored with a click. Dragging on a page draws a box with the replacement text from the field next to the buttons (no dialog); with *Maske zeichnen* it draws a black mask that removes text and image under it and writes nothing; Shift + drag pans the view. Discarded hits can be remembered per patient in the pseudonym store (box in the review step, stored on export): next time the same text under the same rule starts out green and can be restored. The recognised text is corrected in the text-recognition step (what the OCR misread in the image is masked in the review, not retyped); the correction feeds the text file, the Markdown and the invisible text layer.

```sh
uv sync --extra gui        # PySide6 (Qt 6)
uv run pseudonymed gui        # or: uv run pseudonymed-gui
```

Eleven steps in one window, labelled in German by default (English names in brackets): **1 Patientendaten** (*Patient data*: address-book search, patient file or vCard; every identifier in an editable field; relatives, referrers and free terms one per line), **2 Identifikatoren** (*Identifiers*: hospitals, occupations, study acronyms, titles and your own entries as a sortable, editable table; redacted by default, hospitals everywhere, occupations only next to a cue such as *arbeitet als*, study acronyms only next to *Studie*, registry numbers always, titles only next to a name found; employment status stays, following the GeMTeX guideline), **3 Fachvokabular** (*Medical vocabulary*: the protected terms as a sortable, editable table with CSV import and export), **4 Dokumente** (*Documents*: drag and drop, paper size, clean-up of scans and photos; a saved working state restores everything up to the review), **5 Texterkennung** (*Text recognition*: OCR engine, language packs, the recognised text for correction), **6 Analyse** (*Analysis*: detection settings, including four independent options for the medical content, all off by default: the drug substance, its dose and schedule, the lab examination, its measurement; recipient key), **7 Sichtprüfung** (*Visual review*: every page with a coloured box per hit; discard false hits, take words into the list, draw boxes or masks over what was missed, save the working state to resume or vary the review later), **8 Kontrolle** (*Control*: re-check and residual-risk estimate), **9 Export** (target folder, options, the report per file), **10 Reidentifikation** (*Re-identification*: paste the model's text, pick the person or open a key capsule, copy or save the result) and **11 Datenbank** (*Database*: storage location, statistics, backup and restore). A discarded hit is remembered: the re-check tolerates exactly that rule and text, everything else still blocks the release. Long steps run in a worker thread; the window never talks to the network except for the address-book search.

### Address book

Two kinds, searched together from step 1 (*Adressbücher einrichten …*, or `pseudonymed kontakte lokal FILE|FOLDER` and `pseudonymed kontakte einrichten`): a local vCard file or a folder of vCard files (export from Apple Contacts, Thunderbird, Outlook or Nextcloud; stays on the machine) and a Nextcloud address book over CardDAV. The app password goes into the operating system's keyring (extra `carddav`, bundled in the desktop app); without a keyring the dialog, or `--passwort-datei`, keeps it in the configuration file, which is readable by the user only. Search results appear in a list that is hidden until there are hits; clicking one fills the fields. *Patientendatei …* loads a JSON or TOML file with the identifiers in the shape `pseudonymed kontakte export` writes (*Vorlage speichern …* gives an empty one), *vCard …* a single card. A text file with one name or term per line can be dropped onto the fields for relatives, referrers and free terms.

`kontakte einrichten` stores server address, user name and address book in the configuration file (`pseudonymed konfig` shows where) and the app password in the operating system's keyring (install the extra: `uv sync --extra carddav`). Without a keyring, set `PSEUDONYMED_CARDDAV_PASSWORT`; `PSEUDONYMED_CARDDAV_URL`, `_BENUTZER` and `_ADRESSBUCH` override the file. Only https is accepted (loopback addresses excepted for tests). The client speaks plain CardDAV (PROPFIND, REPORT addressbook-query) and needs no third-party library.

Cards written by DoctoNext and hand-made cards are both understood: `N` (salutation prefix gives Herr/Frau), `GENDER`, `BDAY`, `TEL`, `EMAIL`, `ADR`, `X-MAIDENNAME`, `X-DOCTOLIB-PATIENT-ID`, and an insurance number found in `NOTE` or `X-KVNR`. Relatives or referrers mentioned in a note are **not** derived automatically: export the card and add them to the patient file.

Options for the pseudonym store: `--schema hash` (default) or `--schema buchstabe` (running letters, `Patient A`); when the patient resembles a stored person without a clear match, the command stops and asks for `--gleich KENNUNG` or `--neu`.

Exit codes: 0 released, 1 input error, 2 not released (check failed or page without text layer), 3 pseudonyms left unresolved after re-identification, 4 uncertain match in the pseudonym store (decide with `--gleich` or `--neu`).

### Scans and photos

Before OCR, image-only pages go through a clean-up (the lower half of the desktop's documents step; on the command line `--aufbereiten auto`, the default, applies the suggestion): the tilt is estimated from the text lines and straightened, a sheet photographed against a background is found and unwarped, shadows and grey paper are evened out, dark scanner borders are cleaned, coloured ink (stamps, highlighter, blue signatures) is dropped, grain and dust are removed, faint copies get more contrast, ruled and table lines can be taken out, pages can be rotated in 90° steps (an *Ausrichtung erkennen* button finds portrait/landscape from the lines and upside-down pages by a short OCR comparison) and turned black and white, and rectangles can be drawn on the result to erase regions white before the OCR ever sees them. Upscaling by 2×, 3× or 4× is not baked into the page but raises the resolution at which the OCR reads it; the *Buchstabenmodus* enlarges with Lanczos and sharpens the strokes in grey scale. Measured on synthetic scans with RapidOCR, a hard local threshold (Sauvola) after the enlargement looked crisp but wrecked the recognition, so the image stays grey; the automatic suggestion never switches the letter mode on, and it straightens only tilts of 1.2° and more, because the engines tolerate a slight tilt and rotating a noisy scan costs a little. A test guards that the suggested clean-up does not lower the OCR accuracy on a noisy, tilted scan. A learnt super-resolution model for text would need extra libraries and models and is not included. Denoising, contrast and sharpening have strength sliders; erased rectangles can be taken back one by one (Cmd/Ctrl+Z). Every step is a suggestion the user checks in a linked before/after view with a movable divider (pan or zoom one side, the other follows; Shift or Option + drag pans; an upscaled result is shown at the original size, zooming in reveals the gain); the processed image replaces the page, so that OCR, redaction and output all work on the corrected page. Needs OpenCV and NumPy, which come with the `ocr` extra.

Install the extras once: `uv sync --extra ocr --extra codes` (RapidOCR with bundled models, pillow-heif, zxing-cpp). A locally installed Tesseract (Homebrew, apt, the Windows installer) is found in the usual places even when the app starts from the Finder and is used when RapidOCR is missing or preferred (`--ocr tesseract`, `[ocr] backend = "tesseract"` in the configuration file, or `PSEUDONYMED_OCR=tesseract`; `--ocr aus` disables OCR). German and English language packs are picked up when installed.

Tesseract and tables: its page segmentation takes a boxed grid for graphics and drops the cells (a bordered medication table came back as a single word). Every page is therefore scanned for grids (long horizontal and vertical rules that touch); each grid is cut out, its rules are removed and the crop is read again as one block; the reading with the higher confidence mass wins the box. Measured on synthetic bordered tables at 200 dpi: 0 of 45 cell words with the plain pass, 42 with the table pass, with thin rules 12 → 42, on a noisy scan 11 → 29; pages without a grid are untouched. The checkbox in the text-recognition step and `--keine-tabellen` switch it off. RapidOCR, a detector-based engine, does not have the problem.

Structured text: OCR delivers lines, a language model wants the document's own structure. By default (`--gliedern`, the checkbox in the text-recognition step; `--roh` for the plain lines) the recognised text goes out as Markdown: lines that run to the right margin are joined into paragraphs (hyphenation undone), a taller gap ends a paragraph, lines in a larger face become headings, short bold lines on their own (ink coverage well above the page's median) become small headings, bullets become list items, and words separated by far more than the usual gap are table cells (a tab in the page text), consecutive such lines a Markdown table. Italics are not marked: the engines report no slant. The structure is computed from the OCR geometry when the page is read and applied after the pseudonyms are in place, so the text file, the Markdown and the correction editor all show it; the text-recognition step shows the structured text, which you correct there.

Text layer on the image: whatever text goes out for a scan, the invisible layer sits on the printed words. For the plain reading every OCR word is written at its own box, sized to the box width. For a corrected or restructured text the words are aligned to the OCR words (longest common subsequence on normalised words); a corrected word takes the box of the word it replaces, several words on one OCR word share its box, words without counterpart are placed between or after their neighbours, and Markdown markup gets no box. Selecting a word in a PDF reader therefore covers the printed word, and a search hit lands where the word is.

Image files are placed on a sheet of paper, A4 by default (`--papier a4|a5|a3|letter|legal|bild`, the combo box in the documents step): portrait or landscape follows the image, which is scaled to fit and centred; `bild` keeps the old behaviour of a page exactly as large as the image. EXIF orientation of phone photos is honoured.

Pages without a text layer, image files (JPEG, PNG, TIFF, HEIC) and pages whose area is largely covered by images are read by OCR after a median filter against scanner noise. Hits are blanked **in the image pixels**: the OCR word box is snapped outward to the next word gap in the image and padded, so that an imprecise box never leaves a character standing; the pseudonym is written on top. The text file gets the OCR text as a separate block marked as unchecked; the output pages are OCR-read again and any leftover blocks the release. Barcodes and QR codes are blanked as `[Code]`.

OCR misreads are met in three ways: codes such as insurance numbers are matched tolerant to the usual confusions (0/O, 1/I, 5/S, 8/B); values behind labels like "Versicherten-Nr.", "Pat.-ID" or "AZ" are blanked even when misread; and every identifier is additionally searched with a small edit-distance tolerance that grows with its length, also across tokens OCR split ("gotthard. flantz@example. org"). Lines OCR could not read at all (fragments, low confidence) are blanked as `[unlesbar]` because what cannot be read cannot be checked (`--unlesbar lassen` keeps them). This also removes handwriting the detector finds but cannot read; handwriting it does not find stays. Preview images of every OCR page are written to `<name>_pseudonym_vorschau/`: look at them before handing a scan to a model, over-covered neighbours and `[unlesbar]` bars show what was lost.

### Texts and transcripts

Plain text goes through the same pipeline: `.txt`, `.md`, `.srt` and `.vtt` files, for instance the transcript a local speech recogniser wrote from a recorded consultation. The output is a text file again, `name_pseudonym.txt` (same extension as the input), with every identifier replaced by its pseudonym and nothing else touched: line structure, SRT and WebVTT timestamps, cue numbers and Whisper-style `[00:00.000 --> 00:04.000]` stamps stay as they are. The report is written as for a PDF, and the re-check runs over the output before it is released.

Two more text-like inputs are rendered first and come out as `.txt`: **Whisper JSON** (openai-whisper, whisper.cpp, WhisperX and plain segment lists) becomes one line per segment, `[00:00:01.000 --> 00:00:03.500] SPEAKER_00: text`; word-level entries and token ids are not carried over, because the token ids encode the clear text and the word copies could not be checked consistently. **E-mails** (`.eml`, as mail programs export them) become From, To, Cc, Date and Subject, the plain-text body (or the HTML body as text) and a list of attachment names; routing headers such as Message-ID and Received are dropped, and attachments are not included: pseudonymise a PDF or photo a patient sent as a file of its own.

Speech recognisers misspell names the way OCR does, so for text files the fuzzy search of the OCR path is on by default (`--genau` switches it off): the patient's identifiers are also searched with a small edit distance, names and places only when capitalised, so that *lang* stays safe for a patient called Lang while *Lanq* is caught. Fuzzy hits are guesses and are shown in orange in the review tab. The review shows the text with coloured spans instead of a page image; click a span to select the hit, select any text and press *Redact selection* to mark what was missed. NER and the medical vocabulary work as for PDFs. Numbers spoken as words are read as digits before matching: "einundzwanzigster Juli neunzehnhundertneunundfünfzig" is the date of birth, "Sieringgasse zweiundvierzig" the street, "acht zwei vier sechs zwei" the postcode; the whole phrase is then replaced by the pseudonym.

### Unknown names (NER, optional)

`uv sync --extra ner` (spaCy and the German model) adds named-entity recognition: `--ner` on the command line or the checkbox in the documents tab tags people and places the rules do not know and gives them reproducible codes (`Person K7Q4MX`, `[Ort 2F7QV4]`). It guesses, so it keeps its hands off everything the medical vocabulary marks (see below), drops ordinary words the model only capitalised because they start a sentence, drops single words the tagger calls common nouns and single words it has never seen (German compounds such as *Nierenlager*, *Strichgang*) unless a salutation, title or kinship word precedes a person or a preposition a place, shows its hits in their own colour in the review tab and never runs in the re-check. The order is fixed: the vocabulary marks the page first, then NER runs and skips every entity inside a marked span; what still slipped through in findings prose ("Konzentration: gut") were terms neither list had, hence the third list below and the noun filter. The graphical interface switches it on by default once the extra is installed, after the vocabulary has marked the page; on the command line it stays opt-in.

### Medical vocabulary (what guesswork must never redact)

NER and the fuzzy OCR search are heuristics, so they run behind a guard: before they look at a page, every medical term on it is marked and those spans are off limits to them. Since November 2026 every term lives in the `vokabular` table of the pseudonym database (term, category, added): the bundled lists are loaded into it on first use, former per-file user lists are taken over once, and the vocabulary step shows the table sorted by any column, lets you edit cells, add and delete terms (bundled ones included) and exchange CSV (`begriff,kategorie`, header optional). The matcher is rebuilt only when the table's version counter changed. Being in the database, the vocabulary is part of every backup. The deterministic rules for the patient's own identifiers are not affected (a patient really called Herz is still redacted). The bundled base vocabulary (`pseudonymed/daten/fachbegriffe_de.txt.gz`, about 40 000 German terms) is built by `werkzeuge/fachbegriffe_wikidata.py` from Wikidata (CC0): German labels and aliases of every item with an ICD-10 code, an ATC code, a WHO INN or a MeSH descriptor in the medical MeSH trees A–G (anatomy, organisms, diseases, drugs, techniques, psychiatry, phenomena; geography and occupations are left out so that towns and surnames stay recognisable). Matching tolerates German inflection, hyphenated compounds (*Parkinson-Syndrom*) and umlaut transliteration, and multi-word terms are matched whole. A second bundled list (`pseudonymed/daten/koerperteile_de.txt`, about 580 entries) covers body parts, organs, bones, muscles, vessels and nerves in everyday German plus the side and position words (links, rechts, proximal …), because the Wikidata list lacks many colloquial forms (Kopf, Nacken, Oberbauch, Wade) and NER liked to take them for names. A third list (`pseudonymed/daten/befundbegriffe_de.txt`, about 370 entries) holds the terms of the clinical examination and the findings report as they head the lines of a status (Konzentration, Haltung, Gangbild, Strichgang, Nierenlager, Reflexe, Sensibilität, Procedere …), which are in neither MeSH nor the body-part list.

Your own vocabulary grows with every review: the export writes the discarded guesses to `<name>_pseudonym.vokabular.txt` (one term per line; discarded hits of the fixed rules are left out, their text is the patient's own identifier), and the vocabulary step (*CSV oder Liste importieren …*), or `pseudonymed fachbegriffe ergaenzen FILE`, takes such a file into the table under the category Nutzervokabular. The vocabulary shields terms from NER and the fuzzy search for every patient; the per-patient *remember discarded hits* box in the review step is the place for rule hits.

Add your own lists with `pseudonymed fachbegriffe importieren` from MeSH XML (`--format mesh-xml`, the NLM file or a translation), from ICD-10-GM, Alpha-ID-SE or ATC tables (`--format csv --spalte N`) or from any plain list; `pseudonymed fachbegriffe pruefen WORT` tells whether a word is protected, `pseudonymed fachbegriffe status` lists the sources. SNOMED CT cannot be shipped (licence), but a locally licensed description file imports like any CSV.

### Pseudonyms for a recipient: key capsules

Patients and colleagues can pseudonymise documents that one person, say their physician, is to read in clear later. The recipient publishes an OpenPGP public key (on the website, in the letterhead); the sender gives PseudonyMed that key (`--empfaenger key.asc` or an https address; in the desktop the group *Empfänger* in the analysis step (5), with the fingerprint shown for comparison by a second channel and pinned in the settings). PseudonyMed then derives all pseudonyms from a one-time key instead of the local secret, writes nothing to the local database, and puts the mapping back to the clear data, together with the patient's name, date of birth and identifier, into a capsule encrypted to the recipient's key: `<name>_pseudonym.kapsel.asc`. The pseudonymised document and the language model's answer may travel as usual; the capsule goes to the recipient only, never to the model. The recipient opens it in step 9 (*Kapsel öffnen*, or `pseudonymed rueckersetzen brief.txt --kapsel brief.kapsel.asc`), with the private key in the GnuPG keyring (the agent asks for the passphrase) or in a key file (`--privater-schluessel`), and every pseudonym comes back, including relatives, referrers and places the recipient's own records never knew; the capsule's patient is matched against the local pseudonym store and the matching entry is named. The one-time key itself travels inside the capsule, so the pseudonyms could also be re-derived from the recipient's master data, but the mapping makes that unnecessary. The design is a key-transport scheme rather than a public-key pseudonym: a pseudonym computed from the public key alone would let anyone with that key enumerate names and dates of birth, whereas a random key wrapped for the recipient reveals nothing.

Engines: the extra `pgp` installs [pysequoia](https://github.com/wiktor-k/pysequoia) (Sequoia-PGP, wheels for every platform, bundled in the desktop app), so a patient needs nothing but the public key. The system's GnuPG is used when present (`gpg --decrypt` for the keyring; it also serves as the encryption engine when pysequoia is missing). Curve25519 and RSA keys work; GnuPG 2.5 exports Curve25519 *secret* keys in a form pysequoia does not read yet, so such keys are used through the keyring. `pseudonymed schluessel erzeugen --name … --email …` makes a key pair for recipients without GnuPG (public key to publish, private key without passphrase to keep safe); `pseudonymed schluessel zeigen KEY` prints fingerprint and names. The recipient's own set-up: `gpg --armor --export <key-id> > pseudonymed.asc`, publish the file and the fingerprint (`gpg --fingerprint <key-id>`).

### Residual-risk estimate (step 7, "Kontrolle")

The re-check proves that the patient's own identifiers are gone. Step 7 asks the next question: do the details that remain, taken together, still single the patient out? The estimate follows the k-map idea of disclosure-risk assessment (El Emam; EMA Policy 0070 and Health Canada with their threshold of 0.09; Rocher, Hendrickx and de Montjoye 2019 for the correctness formula): every remaining quasi-identifier has a population frequency, the expected number of people in the reference population who share all of them is λ = N · Π f, and κ = (1 − e^−λ)/λ is the chance that a match is the right person. Bits (−log₂ f) make the contributions comparable, about 26.3 bits single one person out of Germany. Counted are sex (1 bit, German prose shows it), the year of birth or age (≈ 6.4 bits, more when an age next to an exact letter date narrows the birthday), the smallest municipality named in the text by its population (Destatis GV-ISys, bundled as `pseudonymed/daten/gemeinden_de.csv.gz`, Datenlizenz Deutschland – Namensnennung 2.0) and the rarest named rare disease by its Orphanet prevalence (bundled as `pseudonymed/daten/orphanet_praevalenz_de.csv.gz`, CC BY 4.0). Only the strongest place and the strongest diagnosis count, further ones are listed; the attributes are assumed independent, which is optimistic for atypical combinations, so the result is a band, not a probability. Lights follow the published thresholds: green from λ ≥ 11 (κ ≤ 0.09, the EMA level), yellow from λ ≥ 5 (the k = 5 of German practice guides), red below. Rule flags name what the model cannot weigh: ages from 90, exact dates of reportable events, occupations and employers, family details, places under 20,000 inhabitants in clear. Documents of the same patient are judged together, and what a released document revealed is remembered per patient (categories and weights, never clear text), so later documents are judged with it. The reference population and the sender's own places (practice, clinic, not the patient's) are settings of the step; `--referenzpopulation` and `--eigene-orte` on the command line. A red estimate does not block the export, but the export then needs an explicit confirmation. The score is a synthesis of published parts, not a published standard, and the report says so; the research behind it is summarised in the project's research report.

### Database: statistics, backup, restore

Step 10 of the desktop (`pseudonymed datenbank status|speicherort|exportieren|importieren` on the command line) shows what the pseudonym store holds, lets you choose where database and key file live, and keeps them safe. Storage location: both files may sit in any folder, even apart from each other (`[speicher]` in the configuration); changing the location copies the current files there (database through the backup API) and renames the old ones `*.verlegt-<timestamp>`, so that exactly one database stays live. Statistics: database path and size, schema, whether the key file exists and a public handle of the key (16 hex digits of its SHA-256, never the key), patients, linked spellings, mappings in total and per category (patient, relatives, referrer, date of birth, street, postcode and town, person and place from NER, telephone, e-mail, insurance number, patient ID, file number, barcode …), remembered discards per rule, first and last entry, SQLite integrity check, pages, vocabulary files, configuration. Backup: a ZIP with a consistent snapshot of the database (SQLite backup API), the key file, optionally `konfig.toml` and the vocabulary folder, plus a manifest with SHA-256 checksums; protected by a passphrase (OpenPGP symmetric encryption, `.zip.gpg`, readable with `gpg --decrypt` too) unless you insist on plain. Restore either replaces database and key (the current ones are set aside as `*.vor-import-<timestamp>`) or merges an archive into the local database, which is allowed only when both were made with the same key, because two pseudonym spaces cannot be mixed. The desktop refuses to import while analysed documents are still waiting for export.

### Languages

The interface is German with an en-GB translation (`pseudonymed gui --language en`, the *Language* menu, or `PSEUDONYMED_SPRACHE=en`); manuals: `docs/anleitung.md` (German), `docs/manual.md` (English). Reports and command-line messages are German.

## What it does not do yet

* Without NER, unknown names (a relative not listed in the patient file) are not found; add them to the patient file (`angehoerige`, `zuweiser`, `begriffe`) or switch NER on and review its hits.
* Handwriting and text inside photos of screens or odd angles are beyond OCR; the review tab shows every page so that you can draw a box over what was missed.
* Office documents (DOCX, ODT) are not read; convert them to PDF or plain text first.

## Safety notes

* All processing is local; the only network connection is the CardDAV request to your own Nextcloud.
* Reports and logs contain no clear data; the mapping lives in an SQLite file in the user data folder next to the secret key for the identifiers (`pseudonymed konfig` shows where). Back up both; the key alone reproduces the identifiers, the database alone does not.
* Names are matched in their written, capitalised and transliterated forms (Müller, MÜLLER, Mueller, Muller, Müllers) but not in lower case, so that surnames which are also words do not fire in running text. Longest match wins, so "Max Müller" becomes one `Patient A`.
* PyMuPDF is pinned below 2.0: that release shifts the glyphs after a redaction (see `docs/pymupdf-redaction-shift.md`). A layout check after every redaction rasterises any page where text moved.

## Bundled data

The data files in `pseudonymed/daten/` are not covered by the AGPL; each carries its source, licence and date in its first line, and each is rebuilt by a script in `werkzeuge/`. Since November 2026 the term lists among them also fill the table `lexikon` of the pseudonym database (term, class, role, source, identifier, details). The lexicon records what a term *is*: medical classes (anatomy, drug, disease, symptom, substance, procedure, psyche, physiology, organism, laboratory value, finding, eponym) and quasi-identifying attributes (occupation, employment status, title, hospital, study). It is kept apart from the protected vocabulary on purpose, so that occupations such as *Bauer* or hospital names never become protected from redaction. Its identifier rows are the table of step 2 and are redacted by default; the medical classes and the control step do not use it yet. It is reloaded whenever a bundled file changes; rows of the source `Nutzer` stay.

## Code quality

`script/quality_metrics.py` is the family's quality battery (the same instrument as in qdaPy, officeQDA and TimeAttest): cyclomatic and cognitive complexity, function length and nesting, module size, duplicated blocks, ruff, mypy, undocumented public definitions, dead-code candidates and test coverage, written as a JSON snapshot. The numbers are calibrated against the project's own history, not against universal thresholds (Nagappan, Ball and Zeller 2006): `quality-baseline.json` is the ratchet, the gated keys must never rise above it, and CI runs the comparison. Improve the code to move a number, or commit a new baseline consciously with `--update`.

```
uv sync --group quality
uv run python script/quality_metrics.py               # measure and compare with the baseline
uv run python script/quality_metrics.py --no-coverage # without the test run
```
